Forecasting · Analytics engineering · Case study 02

A sales forecast that tells you how wrong it is.

Most sales reports explain last quarter. I built a small but complete pipeline that predicts the next 30 days by region, and is honest about how far to trust it.

Role
Solo: pipeline, model, dashboard
Horizon
30-day forecast, per region
Stack
Python, Postgres, dbt, Docker, Streamlit
Code
GitHub ↗

01 — The questionWhat is likely to happen next, region by region?

Sales managers usually get static reports that describe what already happened. I wanted them to see what is coming: which regions are trending down, which managers are pulling ahead, and what the next month probably looks like. And I wanted them to see it in a tool they can filter themselves, not a PDF.

02 — The pipelineFive steps, each one testable

  1. Ingest. Raw retail sales from Excel load into a Postgres “raw” schema, running in Docker.
  2. Model. dbt turns raw tables into staging, intermediate and mart layers, with data tests at each step.
  3. Export. The daily-by-region sales mart is exported for modelling.
  4. Forecast. Each region gets its own Holt-Winters model (additive trend with damping, weekly seasonality) that projects 30 days ahead.
  5. Explore. A Streamlit and Plotly dashboard shows KPIs, trends and the forecast overlay, filterable by region and manager.

GitHub Actions runs the entire chain against a real Postgres service container on every push, not just a linter. If a dbt test or forecast step breaks, the build breaks.

Design choiceBefore it forecasts the future, the model forecasts the most recent 30 days it already knows, and reports how far off it was.

03 — The findingDaily forecasts are directional, and I said so

The backtest is the point of this project. On held-out data, daily-grain error (MAE) ran at 85–135% of average daily sales. At this volume, daily store sales are just very noisy. Many portfolios would bury that number. I put it front and centre in the README, because a manager who trusts a daily forecast too much will make worse inventory calls than one who knows to read it as a trend.

The fix is also clear from the data: aggregate to weekly grain, where the noise averages out and accuracy improves considerably. That is the first item on the roadmap.

04 — Where AI comes in nextDashboards that explain themselves

  • Weekly-grain and product-category forecasts for materially better accuracy.
  • LLM-generated narrative summaries that tell a manager what changed this week and the likely reason, in plain English, next to the chart.
  • Scheduled runs (Airflow or a GitHub Actions cron) and a deployed dashboard.
